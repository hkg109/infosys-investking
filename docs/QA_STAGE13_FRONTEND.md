# QA 13단계 Frontend — 커스텀 액션 오버레이

## 구현 범위

`F-28~30`의 목록·편집·상세 동작을 공통 `ActionDialog`로 통합했다. 데스크톱은 우측
Drawer, 640px 이하는 하단 Sheet로 표시한다. 브라우저 기본 확인창은 사용하지 않는다.

| 화면 | 변경 내용 |
|---|---|
| 종목 | 추가·수정 Drawer, 참조 기록을 포함한 비활성화 확인창 |
| 사건·배정 | 사건 추가·수정 Drawer, 삭제 확인창, 월별 배정 대형 Drawer |
| 비밀 미션·시장정보 | 추가·수정 Drawer, 기록 보존 안내가 있는 비활성화 확인창 |
| 참가자 | 목록은 요약만 표시하고 현금·평가액·종목별 보유량을 관리자 상세창에 표시 |
| 주문 | 인라인 입력을 주문 전용 Drawer/Sheet로 이동, 처리 중 재진입 차단 |
| 거래 이력 | 각 체결 건의 가격·수량·시각·실현손익 상세창 추가 |
| 게임 초기화·페이지 이동 | 브라우저 기본 UI 대신 동일한 커스텀 확인창 사용 |

## 공통 동작

- `role="dialog"`, `aria-modal`, 제목 연결을 제공한다.
- 열릴 때 첫 입력에 포커스를 주고 닫힐 때 열기 버튼으로 포커스를 돌려준다.
- Tab/Shift+Tab 포커스를 창 안에 가두며 ESC·닫기·배경 클릭 동작을 통일한다.
- 저장·요청 중에는 닫기와 중복 제출을 막는다.
- 편집 초안이 있으면 ESC·닫기·취소·배경 클릭 모두 “계속 편집/변경사항 버리기”를 거친다.
- 창이 열려 있는 동안 본문 스크롤을 잠근다.
- 모바일에서는 화면 높이 92dvh 이내의 Sheet와 내부 스크롤을 사용한다.

## 기본 UI 커스텀 범위

프로덕션 화면의 select, checkbox, radio, progress, details/summary, 스크롤바, 포커스 링,
버튼 hover/disabled 상태를 공통 스타일로 통일했다. 의미와 키보드 접근성을 보존하기 위해
폼 요소 자체는 HTML 표준 요소를 유지하되 브라우저 기본 외형만 제거했다.
