# 6단계 — 순위·최종 결과 화면

## 구현
- 사용자 게임 화면 상단에서 서버 계산 TOP 3, 참가자 수, 내 순위와 현금/주식 평가액/총자산을 표시한다.
- TOP 3은 배열의 첫 3명이 아니라 서버가 제공하는 공동 3위까지 전원 표시한다.
- `ranking:update`를 기존 게임 Socket.IO 연결에서 수신하면 게임 정보와 순위 HTTP 조회를 갱신한다. 5초 폴링, 재접속, 탭 복귀, 수동 새로고침으로 누락된 알림을 복구한다.
- 개인 순위는 세션 쿠키를 사용하는 `/api/rankings` 응답의 `me`만 사용한다. 공개 소켓 데이터로 사용자를 추측하지 않는다.
- `ranking.final`이 true일 때만 확정된 최종 결과로 표시한다. 게임 종료 후 확정 전 응답은 명확하게 구분한다.
- 로딩, 빈 목록, 개인 순위 미포함, 인증 만료, 네트워크 실패와 마지막 조회 결과를 구분한다. 없는 값을 0위/0원으로 바꾸지 않는다.
- 로그아웃/계정 변경 후 이전 사용자 결과나 늦게 도착한 요청이 표시되지 않도록 요청 정리와 사용자 ID 검사를 적용한다.

## 서버 보완
게임 종료 알림 직후 HTTP 조회가 마지막 사건 처리보다 먼저 최종 순위를 동결할 수 있었다. 순위 사용자/관리자 조회 및 참가 후 순위 갱신이 기존 게임 이벤트 처리 큐를 기다리도록 연결했다. 순위 계산식과 기존 최종 스냅샷 보존 방식은 그대로 사용한다.

## 검증
- 프론트엔드 테스트 21개 통과, Vite 배포 빌드 통과.
- 실제 로컬 PostgreSQL 서버 테스트 16개 통과(생략 없음).
- 최종 결과 요청을 보류한 상태에서 마지막 주가 변경을 적용하고, 변경 후 자산으로 최종 확정되는 경합 회귀 테스트.
- 동점자 4명 모두 노출, 닉네임 HTML 이스케이프, 확정 전/후, 빈 순위와 개인 결과 없음, 잘못된 API 데이터, 세션 인증 테스트.
- 브라우저에서 기존 종료 게임의 최종 순위 1위/총자산 998,000원/현금 980,000원/주식 평가액 18,000원 표시 확인.
- 실제 iframe 화면 너비 320/360/390/412/430/768px에서 가로 넘침 없음 확인.
- 실물 iPhone Safari 및 삼성 Android 브라우저의 터치·키보드·백그라운드 복귀 검증은 기기 연결 후 행사 전 수행해야 한다. CSS 너비 검증은 실기기 테스트와 다르다.

## 실행
기존 DB 마이그레이션이 적용된 상태라면 추가 스키마 변경 없이 서버와 클라이언트를 재시작한다.
