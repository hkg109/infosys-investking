# QA 7단계 Frontend — 월별 거래·주가 분석

## 구현 범위

- `F-15`: 로그인한 참가자의 전체 또는 월별 체결 내역과 서버 계산 요약을 표시한다. 매수·매도 금액, 순현금흐름, FIFO 실현손익을 클라이언트에서 다시 계산하지 않는다.
- `F-16`: 시장 종목을 선택하면 월별 시가, 장중 사건 직후 가격, 종가를 선형 차트와 텍스트 타임라인으로 표시한다. 전체 기간과 개별 월을 선택할 수 있다.
- `F-17`: 시장 종목, 포트폴리오, 실시간 시세, 매수·매도 탭, 주문 요약을 하나의 투자 흐름으로 연결한다. 종목 목록에서 선택한 종목이 차트와 주문 화면에 함께 반영된다.

## 데이터·보안 기준

- 거래 내역은 사용자 세션 쿠키가 적용되는 `GET /api/trading/history`만 사용하며 다른 참가자의 정보는 조회하거나 표시하지 않는다.
- 주가 차트는 `GET /api/trading/companies/:companyId/history`의 `history[].snapshots`를 시간순으로 사용한다.
- 금액, 실현손익, 변동률은 서버 응답을 표시하며 브라우저에서 금융 결과를 재계산하지 않는다.
- 잘못된 월, 인증 만료, 종목 삭제, 네트워크 실패, 잘못된 응답 구조를 서로 구분해 안내한다.
- 등락은 색상뿐 아니라 `+/-` 부호, 매수·매도 문구, 사건명으로도 구분한다.

## 자동 검증

```bash
cd client
npm test
npm run build
```

자동 테스트는 API 경로·세션 쿠키·캐시 방지, 응답 구조 검증, 중복 거래 방지, 매수 실현손익 비노출, 월 필터, 동일 가격 차트, 장중 사건 상세 표시를 확인한다.

2026-09-18 기준 Frontend 테스트 53개가 모두 통과했고 Vite 배포 빌드도 통과했다. 실제 PostgreSQL 데이터와 다중 브라우저를 사용하는 확인은 아래 목록과 통합 QA에서 별도로 진행한다.

## 브라우저 확인 목록

- [ ] 시장 종목을 누르면 선택 강조, 차트 제목, 주문 종목이 함께 바뀐다.
- [ ] 전체/월별 차트에서 시가·장중 사건·종가 순서와 가격이 서버 데이터와 일치한다.
- [ ] 장중 사건이 없는 월과 가격이 변하지 않은 월도 차트가 정상 표시된다.
- [ ] 주문 체결 뒤 입력 양식이 초기화되고 자산·거래 내역이 갱신된다.
- [ ] 월별 거래 요약과 개별 체결의 금액·실현손익이 API 응답과 일치한다.
- [ ] 320px, 390px, 768px에서 차트, 주문, 거래내역에 가로 페이지 스크롤이 생기지 않는다.
- [ ] 세션 만료와 서버 중단 상태에서 기존 데이터를 다른 계정 정보로 오인하지 않는다.

관리자 권한으로 특정 참가자의 거래를 조회하는 API는 Backend 운영·진단용 계약으로 유지한다. 이번 `F-15~17` 참가자 화면에서는 본인 거래만 노출한다.
