# QA 30단계 — 구매·뉴스·알림 UX

## 완료 범위

- 정보 구매 인라인 확인 영역을 공통 `ConfirmDialog` 기반 Modal로 교체했다.
- Modal은 제목, 가격, 현재 현금, 구매 후 현금을 표시하며 `취소`와 `구매` 동작만 제공한다.
- 요청 중에는 닫기·overlay·Esc·버튼 동작을 잠그고, 실패 시 오류를 Modal 안에 유지한다.
- 정보 구매 POST는 사용자 재시도 없이 한 번만 전송하며 성공 응답으로 현금·상점·보관함을 함께 갱신한다.
- 뉴스 탭과 이동·크기 조절 가능한 플로팅 뉴스 창이 같은 `useEventNews` 상태를 공유한다.
- 뉴스 탭에 `뉴스 창으로 보기`를 추가하고, 사건 알림을 누르면 같은 창의 해당 기사로 이동한다.
- 장중 사건 Socket을 `WARNING`, `HALTED`, `APPLYING`, `CLOSED` 상태로 합성한다.
- 발생 전 카운트다운, 거래정지 종료 예상 시간, 주가 반영 중, 거래 재개 완료를 제목과 함께 표시한다.
- 알림 상태에는 기사 본문·사건 결과·변동률을 저장하지 않는다.
- 같은 사건 ID는 한 알림으로 갱신하며, 종료 알림은 8초 뒤 자동으로 제거한다.
- 대기 안내를 시장·주문 본문에서 제거하고 오른쪽 아래 safe-area 알림으로 이동했다.
- 연결 상태를 `INFOSYS INVESTKING` 브랜드 옆으로 이동하고 오류·재연결 상태에서는 업데이트 버튼을 유지했다.

## 검증 기준

- 구매 Modal 배경 blur, 포커스 이동·잠금, Esc·overlay·요청 중 닫기 차단
- 구매 성공·실패와 중복 POST 방지
- 뉴스 탭·플로팅 창의 단일 데이터 상태
- 30초·45초·65초 사건 카운트다운
- 예고·정지·반영·마감 상태와 비공개 내용 차단
- 대기 알림이 본문 레이아웃 높이에 영향을 주지 않는지 확인
- 데스크톱·모바일 헤더 연결 표시와 safe area 확인
