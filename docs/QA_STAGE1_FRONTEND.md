# QA 1단계 Frontend — 관리자 인증·기본 사용성

## 기준과 범위
2026-09-16 전달받은 DEVELOPMENT_HANDOFF.md의 QA 1단계 F-01~05를 적용한다. 이전 기능 개발 1단계와 구분한다. 선행 Backend PR #15는 main에 병합된 상태다. 참조된 QA_DEVELOPMENT_PLAN.md는 제공 파일 및 저장소에서 발견되지 않아 인계서의 다섯 항목과 실제 API 계약을 기준으로 구현했다. 이후 단계 기능은 이번 PR 범위에 포함하지 않는다.

## 구현
- F-01: POST /api/admin/auth/verify의 authenticated=true 확인 후에만 대시보드와 사건 관리 컴포넌트를 마운트한다. 빈 비밀번호, 잘못된 비밀번호, 서버 미설정, 연결 실패, 중복 제출을 처리한다. 비밀번호는 컴포넌트 메모리에만 유지하고 관리자 잠금·페이지 이탈·새로고침 시 폐기한다. 각 관리 요청의 서버 Bearer 인증은 그대로 필요하다.
- F-02: 정상 연결은 작은 상태 문구로 표시한다. 로딩·오류·연결 복구 상태는 안내 영역에 표시하고 실패 시 재조회 버튼을 제공한다.
- F-03: 체결이 확인된 주문마다 한 번만 종목/거래 종류/수량/입력 오류를 초기화한다. 체결 내역은 유지하며 후속 폴링은 작성 중인 새 주문을 지우지 않는다. 수동 입력 초기화 버튼도 제공한다. 처리 중이거나 미확인 주문이 있으면 폼과 초기화를 잠근다.
- F-04: 참가 화면에 계정 복구, 뉴스·사건, 거래 조건, 거래 중지, 최종 순위 규칙을 안내한다. 서버 설정에 따라 달라지는 초기 자금/시간을 고정 숫자로 안내하지 않는다.
- F-05: 내 정보에서 닉네임, PIN을 표시하지 않는 이유, 계정 복구 방법과 로그아웃을 제공한다. 주문 처리 중 로그아웃을 막으며 미확인 주문 복구 안내와 로그아웃 실패 재시도를 제공한다.

## 검증
- client 테스트 25개 통과, Vite 배포 빌드 통과.
- 실제 PostgreSQL server 테스트 26개 통과, skip 없음.
- 격리된 로컬 QA DB와 API(3001), 프론트엔드(5174)로 브라우저 검증.
- 관리자 잘못된 비밀번호 차단 → 올바른 비밀번호로 대시보드 → 새로고침 재인증 → 관리자 잠금 확인.
- 참가자 가입 → 관리자 게임 시작 → A 종목 2주 체결 → 종목 미선택/매수/수량 1 초기화와 체결 내역 유지 확인.
- B 종목 3주 새 입력 후 자산 재조회 시 입력 유지, 수동 초기화 확인.
- 내 정보 → 로그아웃 → 같은 닉네임/PIN 복구 후 현금 980,000원과 주식 평가액 20,000원 유지 확인.
- 홈/내 정보 포함 게임 화면 320/390/412px에서 document 폭과 scroll 폭 일치. 관리자 로그인은 320px 화면 시각 확인.
- 관리자·참가자 브라우저 수집 콘솔 error 없음.

## 후속 검증
실물 iPhone Safari와 삼성 Android의 터치·키보드·백그라운드 복귀 및 다중 독립 브라우저 세션 행사 리허설은 미실행이다. 위 CSS 너비·로컬 브라우저 검증과 구분한다. 게임 초기화/참가자 관리(2단계), 복수 사건 편집(4단계) 등은 각 후속 Frontend 단계에서 연결한다.

이번 PR은 Backend API나 DB 스키마를 변경하지 않는다. 최신 main Backend를 실행하고 기존 .env의 ADMIN_PASSWORD, CLIENT_URL, DATABASE_URL을 설정해야 한다.
