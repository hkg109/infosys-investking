# QA 4단계 — 복수 사건·월별 배정 UI (F-09~10, D-01)

최신 `origin/main`의 QA 3단계 PR #24 병합 커밋 `db748ab`에서 시작했습니다.

## 사용 방법

1. `/admin` 로그인 후 **사건 목록 조회**를 누릅니다. 사건 원본은 제목·뉴스·결과·여러 기업의 변동률을 편집합니다.
2. **배정 행 추가**에서 월·사건·발생 구분·표시 순서를 정합니다. 장중 사건은 월 시작 후 발생 초와 발생 몇 초 전 예고할지 입력합니다.
3. **수동 배정 검토 → 배정 교체 확정**으로 전체 배정을 저장합니다. 미배정 월에는 사건이 없고, 빈 초안을 저장하면 전체 게임이 사건 없이 진행됩니다.
4. 무작위 배정은 월별 장중·마감 사건 수(각 0~3)와 예고 초를 설정하고 검토·확정합니다. 사건 수 부족, 중복, 시간 충돌은 안내합니다.
5. **서버에 저장된 월별 배정**에서 저장 결과를 확인합니다. 서버 재조회는 입력 초안을 유지하며 **서버 배정으로 초안 되돌리기**를 누르면 초안에 반영합니다.

## 동작과 제한

- 게임 대기 중에만 사건·배정 변경 가능. 처리 중에는 다른 관리자 변경과 게임 제어를 잠급니다.
- 같은 사건은 게임 전체에서 1회, 월별 최대 10개, 표시 순서는 월 내 중복 불가.
- 장중 예고 시작부터 거래정지 종료까지 겹치는 구간을 검사합니다. 거래 종료 시각과 겹치는 사건도 거부합니다.
- 비활성 종목이 포함된 사건은 신규 배정에서 제외하며 사건 편집에서는 비활성 종목을 표시합니다.
- 오류 시 재조회 전 변경을 잠그고 사건·배정 초안을 유지합니다. 자동 재전송하지 않습니다. 재조회 후 저장된 배정과 비교합니다.
- 참가자 뉴스는 현재 월의 모든 사건을 표시하며 사건별 적용 여부에 따라 결과를 공개합니다. 기존 단일 `event` 응답도 호환합니다.
- 사건 배정을 한 번도 저장하지 않은 게임은 기존 서버 동작대로 시작 시 월별 마감 사건 1개를 자동 배정합니다.

## API 변경·업데이트

`GET /api/events/admin/schedule`에 `constraints`(총 월 수, 거래 시간 ms, 최소 거래정지 ms)를 추가했습니다. 서버와 프론트엔드를 함께 업데이트해야 합니다. 기존 응답 필드는 유지하며 DB migration 추가는 없습니다.

D-01 범위로 `EVENT_API.md`의 시간 규칙·응답 계약과 `PROJECT_SPEC.md`의 복수 사건 UI 규칙을 갱신했습니다.

## 검증 — 2026-09-17

- Frontend 자동 테스트 40개 통과, 배포 빌드 및 `git diff --check` 통과.
- PostgreSQL 17 격리 DB로 Backend 테스트 29개 통과, 건너뜀 없음. 실제 API constraints 응답 검사 포함.
- 브라우저 + 실제 API/DB: 사건 4개 생성, 같은 월 장중 사건 2개 수동 저장, 빈 다음 월, 재조회 복구 확인.
- 겹치는 장중 시각 저장 차단 후 수정·저장 성공 확인.
- 매월 장중 1개 + 마감 1개 무작위 배정 및 저장된 시각·예고·순서 표시 확인.
- 게임 시작 후 배정 수정 차단. 참가자 화면에 두 뉴스 표시, 장중 사건 결과만 먼저 공개되고 마감 사건은 결과 비공개 유지 확인.
- 관리자 브라우저 콘솔 오류·경고 없음. 320/360/390/412/430/768px에서 실제 배정 폼 가로 넘침 없음.
- 실물 아이폰·삼성폰 테스트는 사용자 합의에 따라 제외.

기존 익명 순위 Backend와 종전 순위 UI의 응답 차이는 QA 5단계 범위입니다. 이번 검증 중 참가자 순위 갱신 경고를 확인했으며 이 PR에서 순위 화면은 수정하지 않았습니다.
