# QA 2단계 — 참가자 관리·게임 초기화 (F-06~07)

## 구현
- 관리자 인증 후 참가자 닉네임, 온라인/오프라인, 현금, 주식 평가액, 총자산, 보유 종목 상세를 표시한다. 빈 결과·로딩·조회 실패·마지막 조회 시각을 구분한다.
- `participants:presence`, 거래·주가 알림, 5초 주기 조회, 재접속 및 탭 복귀를 통해 관리자 인증 API를 다시 조회한다. 공개 Socket 신호에는 참가자 개인정보를 추가하지 않는다.
- 관리자 상단 접속 참가자 수를 실제 참가자 API와 연결한다. 같은 사용자의 다중 탭은 서버 기준으로 한 명이다.
- 게임 종료 상태에서만 초기화 검토 버튼을 활성화한다. 삭제/보존 범위와 재가입 필요성을 안내하고, 체크박스와 ‘초기화’ 입력 후 최종 확정한다.
- 초기화 처리 중 다른 게임 제어를 잠근다. 응답 실패 시 자동 재전송하지 않고 명시적 결과 조회를 요구한다. 대기 상태 복귀 확인 후 별도 새 게임 시작 버튼을 제공한다.
- 초기화·강제 Socket 해제·재접속 시 참가자 HTTP 세션을 재확인하여 무효화된 참가자를 참가 화면으로 이동한다.

## 브라우저에서 발견한 API 연결 보완
세션 쿠키 Path는 `/api`인데 Socket.IO는 기본 `/socket.io`여서 실제 브라우저 참가자가 오프라인으로 집계되었다. 쿠키 범위를 확대하지 않고 서버·클라이언트 Socket 경로를 `/api/socket.io`로 맞추고 Vite WebSocket 프록시를 추가했다. 서버 및 클라이언트를 함께 업데이트해야 한다. 별도 reverse proxy를 사용하면 해당 경로의 upgrade도 전달해야 한다.

## 검증
- client 테스트 29개, 실제 PostgreSQL server 테스트 29개 통과(skip 없음), Vite build 성공.
- 격리 DB `investking_stage2`, 로컬 API 3001/클라이언트 5174에서 검증.
- 브라우저 관리자 인증 → 참가자 가입 → 다중 탭 온라인 1명 및 자산 표 표시 확인.
- 실제 관리자 초기화 확인 단계와 취소, 진행/대기 중 초기화 비활성화 확인.
- `test/reset-harness.html`의 DB 미연결 모의 화면에서 확인 전 확정 비활성화, 응답 유실 시 제어 잠금, 요청 1회 유지, 상태 재조회 후 새 게임 시작 검증.
- 격리된 QA DB에 API 초기화를 실행하여 참가자 화면의 참가 페이지 복귀, 관리자 재조회 시 참가자 0명, 실제 게임 시작 버튼으로 재시작 확인.
- 관리자 참가자 표 320/390/412/768px 및 확인 폼 320px에서 문서 가로 넘침 없음. 표 자체는 키보드와 가로 스크롤로 탐색 가능.

사용자 결정에 따라 실물 iPhone·삼성폰 검증은 범위에서 제외한다. 브라우저 기능 흐름과 모바일 너비 검증을 완료 기준으로 사용한다.

## 범위
종목 관리/복수 사건 편집/익명 순위 UI 등 다른 QA 단계는 포함하지 않는다. 특히 main의 익명 순위 Backend와 기존 순위 UI 계약 차이는 QA 5단계에서 연결한다. 이번 변경에는 DB 스키마 변경이 없다.
