# QA 33~36단계 통합 개발 계획

## 1. 문서 목적

이 문서는 행사 전 참가자·관리자 화면 추가 QA 15건을 **4개 단계, 브랜치 1개, PR 1개**로 압축해 개발하기 위한 기준이다.

- 통합 브랜치: `codex/qa-rpg-inventory-admin-tables`
- 통합 PR: 위 브랜치에서 `main`으로 1개만 생성
- 개발 방식: 단계별 독립 커밋을 같은 브랜치에 계속 추가
- 병합 시점: 33~36단계 자동 테스트와 실제 브라우저 리허설이 모두 끝난 뒤 한 번에 병합
- 효과음 정책: BGM과 외부 음원은 사용하지 않고 프로젝트 전용 짧은 효과음을 직접 제작

## 2. QA 요구사항 원문 정리

1. 알림·성공·오류 등에 사용할 짧은 효과음을 추가한다.
2. 보관함을 정보상점과 유사한 RPG 인벤토리 형태로 바꾸고 한 줄에 3개씩 표시한다.
3. `주문·보유` 탭 진입만으로 주문창이 자동으로 열리지 않게 한다.
4. `주문·보유` 화면의 `주문하기` 영역을 맨 위로 이동한다.
5. 모든 `~ 업데이트` 버튼을 별도 SVG 아이콘 버튼으로 통일하고 표시 텍스트를 제거한다.
6. 참가자 메뉴의 `시장`을 `시장 종목`으로 변경한다.
7. 단서를 실제 사건과 연결하고 이미 적용된 사건의 단서는 상점에서 숨긴다. `연관없음`을 지원해 가짜 정보도 판매한다.
8. 시장·주문보유 화면의 파란색 `대기/게임중/종료` 상태 영역을 제거한다.
9. 관리자 사건 배정·정보 관리·종목 조회를 직관적인 표로 바꾸고 기존 기능 버튼은 유지한다.
10. 현재 월·보유 현금·주식 평가액·총자산을 게임 화면 상단 고정 내비게이션 바로 옮긴다.
11. 월별 거래 현황을 한 화면의 표로 표시하고 기존 동작 버튼은 유지한다.
12. 주문창을 가운데 플로팅 창으로 열고 연동된 포트폴리오 창을 바로 옆에 표시한다. 주문창을 닫으면 둘 다 닫는다.
13. `매수·매도 주문 열기`를 `주문하기`로 변경하고 버튼을 더 크고 잘 보이게 한다.
14. 타이머는 처음부터 플로팅 창으로만 표시하고 각 탭 상단의 인라인 타이머 영역을 제거한다.
15. 관리자 사건 배정의 `발생` 용어를 실제 동작에 맞게 `주가 변동`으로 바꾸고, 사건별로 월 시작 후 몇 초에 뉴스를 공개할지 별도로 설정한다.

## 4. 33단계 — 공통 기반과 사건 연동

### 4.1 단서-사건 DB 모델

`intelligence_clues`에 nullable `event_id`를 추가한다.

```sql
ALTER TABLE intelligence_clues
ADD COLUMN IF NOT EXISTS event_id UUID REFERENCES events(id) ON DELETE SET NULL;
```

- `event_id`가 실제 사건 UUID이면 실제 사건 연동 정보다.
- `event_id=NULL`이면 관리자 화면의 `연관없음`이며 가짜 정보로 취급한다.
- 사건 삭제 시 단서는 삭제하지 않고 `NULL`로 바뀌어 보존된다.
- 기존 24개 단서는 제목 문자열 추측이 아니라 현재 DB의 고정 UUID 매핑으로 관련 사건을 연결한다.
- migration은 여러 번 실행해도 같은 결과가 되는 idempotent 방식으로 작성한다.

### 4.2 상점 노출 규칙

참가자 공개 상점의 단서는 다음 조건을 모두 만족해야 한다.

1. 단서가 활성 상태다.
2. `available_round <= currentRound`다.
3. 참가자가 아직 구매하지 않았다.
4. 실제 사건과 연결된 경우 해당 게임의 사건이 아직 적용되지 않았다.

추가 규칙은 다음과 같다.

- 연결 사건의 `game_events.applied_at`이 존재하면 공개 상점에서 즉시 제외한다.
- 현재 월이 연결 사건의 배정 월을 지났는데도 미적용 상태라면 운영 오류로 간주하고 상점에서 제외한다.
- `event_id=NULL`인 가짜 정보는 사건 적용 여부와 관계없이 공개 월·활성 상태로만 판단한다.
- 이미 구매한 단서는 사건이 지나도 `intelligence_purchases` 스냅샷을 이용해 보관함에 계속 남긴다.
- 구매 POST에서도 같은 조건을 트랜잭션 내부에서 다시 검증해 화면 갱신 지연을 악용한 구매를 막는다.

### 4.3 API 계약

관리자 단서 DTO에 다음 필드를 추가한다.

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| `eventId` | UUID 또는 `null` | 연동 사건 |
| `eventTitle` | 문자열 또는 `null` | 관리자 표 표시용 사건명 |
| `eventState` | `UNRELATED`, `UNASSIGNED`, `UPCOMING`, `APPLIED` | 현재 게임 기준 상태 |

관리자 생성·수정 요청은 `eventId`를 받으며 빈 값은 `null`로 정규화한다. 존재하지 않는 사건, 중복 필드, 잘못된 UUID는 거부한다.

### 4.4 뉴스 공개와 주가 변동 시점 분리

관리자가 이해하기 어려운 `발생`과 상대적인 `사전 예고` 용어를 제거하고 다음 두 시점을 명시적으로 사용한다.

| 관리자 표시 | API 필드 | 의미 |
| --- | --- | --- |
| 뉴스 공개 | `newsRevealOffsetSeconds` | 월 시작 후 몇 초에 뉴스 제목·사전 기사 내용을 참가자에게 보여줄지 |
| 주가 변동 | `triggerOffsetSeconds` | 기존 API 호환 필드. 월 시작 후 몇 초에 사건 결과와 주가 효과를 적용할지. 거래 마감 사건은 `null` |

DB에는 `game_events.news_reveal_offset_ms`를 추가한다.

```sql
ALTER TABLE game_events
ADD COLUMN IF NOT EXISTS news_reveal_offset_ms INTEGER;
```

- `news_reveal_offset_ms`는 월 시작 기준 절대 시각이다.
- 장중 사건의 `trigger_offset_ms`는 실제 주가 변동 시각으로 유지한다.
- 마감 사건은 `trigger_offset_ms=NULL`을 유지하며 주가 변동 시각은 거래 마감이다.
- 기존 `preannounce_ms` 데이터는 `trigger_offset_ms - preannounce_ms`로 뉴스 공개 시각을 계산해 migration한다.
- 기존 `warning_sent_at`은 DB 호환을 위해 유지하되 의미를 `뉴스 공개 완료 시각`으로 명확히 문서화한다.
- 신규 API와 화면에서는 `preannounceSeconds`를 노출하지 않는다.

검증 규칙은 다음과 같다.

- 뉴스 공개 시각은 0 이상의 정수 초다.
- 장중 사건은 `뉴스 공개 < 주가 변동 < 거래 종료`여야 한다.
- 마감 사건은 `뉴스 공개 < 거래 종료`여야 하며 주가 변동은 거래 마감으로 고정한다.
- 같은 사건의 뉴스 공개는 한 번만, 주가 변동도 한 번만 처리한다.
- 서버 재시작 시 공개 시각만 지났다면 뉴스만 복구하고, 변동 시각까지 지났다면 뉴스 공개 후 주가 변동을 순서대로 보정한다.
- 뉴스 공개 단계에서는 사건 결과와 등락률을 노출하지 않는다.
- 주가 변동 단계에서 결과 기사와 실제 등락을 공개한다.
- 장중 사건 효과음은 뉴스 공개 시 한 번만 재생하고 Socket 재연결로 반복 재생하지 않는다.

### 4.5 직접 제작 효과음

외부 음원과 BGM을 사용하지 않고 짧은 프로젝트 전용 효과음을 직접 제작해 저장한다.

| 파일 | 길이 목표 | 사용 위치 |
| --- | ---: | --- |
| `notification.wav` | 0.3~0.5초 | 일반 알림·대기 상태 변경 |
| `breaking-news.wav` | 0.5~0.8초 | 장중 사건 예고·발생 |
| `order-success.wav` | 0.2~0.4초 | 매수·매도 체결 |
| `purchase-success.wav` | 0.3~0.5초 | 정보 구매 완료 |
| `error.wav` | 0.2~0.4초 | 주문·구매 실패 |
| `month-close.wav` | 0.5~0.8초 | 거래 마감·결과 전환 |

- 파일은 단순 파형을 조합해 직접 생성하고 제작 출처를 문서에 남긴다.
- 브라우저 자동재생 정책 때문에 최초 클릭 전에는 재생을 시도하지 않는다.
- 최초 사용자 상호작용에서 오디오 컨텍스트를 활성화한다.
- 기본 음량은 작게 설정하고 전역 음소거 버튼과 `localStorage` 설정을 제공한다.
- 같은 Socket 이벤트가 재수신돼도 사건 ID·주문 ID 기준으로 한 번만 재생한다.
- 화면 읽기 알림을 효과음으로 대체하지 않고 기존 텍스트·ARIA 상태를 유지한다.

### 4.6 SVG 업데이트 아이콘

`client/src/assets/icons/refresh.svg`를 직접 제작하고 `RefreshIconButton` 공통 컴포넌트를 만든다.

- 화면에는 SVG만 표시하고 `업데이트` 텍스트는 표시하지 않는다.
- `aria-label`, `title`, 로딩 상태는 반드시 유지한다.
- 최소 클릭 영역은 44×44px로 한다.
- 회전 로딩 애니메이션은 `prefers-reduced-motion`에서 비활성화한다.
- `rg "업데이트" client/src`로 남은 텍스트 버튼을 전수 검사한다.
- 대상에는 참가자, 관리자, 뉴스, 정보상점, 보관함, 순위, 거래내역, 주가이력, 연결상태가 포함된다.

## 5. 34단계 — 게임 셸과 주문 워크스페이스

### 5.1 상단 고정 자산 바

게임 내 모든 탭에서 내비게이션 바로 아래에 다음 값을 표시하는 고정 바를 둔다.

| 항목 | 값 |
| --- | --- |
| 현재 월 | `currentRound / totalRounds` |
| 보유 현금 | 투자 지갑 현금 |
| 주식 평가액 | 현재가 × 보유량 합계 |
| 총자산 | 현금 + 주식 평가액 |

- `position: sticky`로 스크롤 중에도 상단에 유지한다.
- 모바일에서는 두 행 또는 가로 스크롤로 정보가 잘리지 않게 한다.
- `주문·보유` 화면에 중복 표시된 기존 자산 요약은 제거한다.
- 데이터가 없거나 재연결 중일 때 0원으로 속이지 않고 로딩·연결 상태를 표시한다.

### 5.2 메뉴와 상태 영역

- 참가자 메뉴 `시장`을 `시장 종목`으로 변경한다.
- 경로 `/game/market`은 유지해 북마크와 기존 링크를 깨지 않는다.
- 시장과 주문보유 화면의 파란색 게임 상태 카드·칩을 제거한다.
- 거래 가능 여부와 오류는 주문 버튼의 disabled 상태 및 접근 가능한 안내로 계속 제공한다.

### 5.3 주문·보유 화면 순서

화면 순서는 다음처럼 고정한다.

1. `주문하기` 주요 CTA
2. 보유 종목 표·카드
3. 주문 결과·오류 안내

- 탭을 클릭하는 것만으로 주문창을 열지 않는다.
- 포트폴리오의 `추가 매수`, `매도`는 기존처럼 종목과 주문 유형을 전달해 주문창을 연다.
- 버튼 문구는 `주문하기`로 통일하고 기존 primary 버튼보다 높이·너비·대비를 강화한다.

### 5.4 플로팅 주문+포트폴리오 창

- `주문하기`를 눌렀을 때 화면 가운데 플로팅 워크스페이스를 연다.
- PC에서는 주문창과 포트폴리오 창을 좌우 2열로 붙여 표시한다.
- 모바일에서는 같은 워크스페이스 안에서 주문창 위, 포트폴리오 아래로 쌓는다.
- 두 창은 선택 종목·현재가·보유량·주문 가능 수량을 공유한다.
- 포트폴리오에서 종목을 선택하면 주문창 종목도 즉시 바뀐다.
- 주문창 닫기, Escape, 배경 닫기 동작은 워크스페이스 전체를 닫아 포트폴리오만 남지 않게 한다.
- 확인 중인 주문이 있으면 기존 dirty/busy 이탈 방지 정책을 유지한다.
- 타이머처럼 헤더 드래그 이동을 지원하되 화면 밖으로 빠지지 않게 제한한다.

### 5.5 플로팅 타이머 기본화

- `FloatingGameTimer`를 처음부터 `docked=false`로 렌더링한다.
- 탭별 상단의 `game-clock-bar`와 인라인 타이머 자리를 모두 제거한다.
- `타이머 띄우기/본문에 고정` 전환 버튼을 제거한다.
- 기존 위치·크기 조절과 저장 기능은 유지한다.
- 작은 화면에서는 자산 바, 주문창, 뉴스 알림과 겹치지 않는 기본 위치를 사용한다.

## 6. 35단계 — RPG 정보상점과 보관함

### 6.1 보관함 인벤토리

- 데스크톱은 한 행 3개 카드인 `grid-template-columns: repeat(3, minmax(0, 1fr))`를 사용한다.
- 태블릿 2개, 모바일 1개로 반응형 변경한다.
- 정보상점과 동일한 카드 크기·테두리·희귀도 느낌을 사용해 RPG 인벤토리처럼 구성한다.
- 카드 기본 상태에서는 제목·구매 월·연동 상태만 표시하고 본문은 노출하지 않는다.
- `정보 읽기` 버튼을 눌러야 상세 모달에서 요약과 전문을 읽을 수 있다.
- 모달 닫기, Escape, 포커스 복귀, 스크롤 잠금을 지원한다.
- 이미 비활성화되거나 사건이 지난 정보도 구매자는 계속 읽을 수 있다.

### 6.2 정보상점 카드

- 실제 사건 단서는 사건 상태를 직접 스포일러하지 않는 범위에서 `미발생 사건 관련 정보`로 표시한다.
- 가짜 정보는 사용자에게 가짜라고 표시하지 않는다.
- 사건이 적용되면 새 응답에서 해당 카드를 제거하고 열린 구매 확인창도 안전하게 닫는다.
- 구매 중 사건이 적용되면 서버의 `CLUE_UNAVAILABLE`을 표시하고 현금을 차감하지 않는다.
- 구매 성공 시 카드가 상점에서 사라지고 보관함에 추가되며 자산 바 현금도 함께 갱신된다.

### 6.3 관리자 단서 편집

단서 편집에 `연관 사건` 선택을 추가한다.

- 첫 옵션은 `연관없음`이다.
- 이후 사건 제목을 월·장중/마감·적용 상태와 함께 표시한다.
- 적용 완료 사건에 새 단서를 연결하려 할 때 경고한다.
- 기존 제목·요약·본문·가격·공개 월·활성 상태 편집 기능은 유지한다.

### 6.4 효과음 연결

- 정보 구매 성공: `purchase-success.wav`
- 구매 실패: `error.wav`
- 장중 예고·발생: `breaking-news.wav`
- 주문 체결: `order-success.wav`
- 월 마감: `month-close.wav`
- 일반 대기·재연결 알림: `notification.wav`

## 7. 36단계 — 관리자 표와 거래 분석

### 7.1 사건 배정 표

| 열 | 내용 |
| --- | --- |
| 월 | 1~12월 |
| 구간 | 장중/마감 |
| 뉴스 공개 | 월 시작 후 N초 |
| 주가 변동 | 월 시작 후 N초 또는 거래 마감 |
| 사건 | 제목 |
| 상태 | 예정/예고/적용/마감 |
| 작업 | 수정·삭제·배정 버튼 |

- 기존 월별 카드와 CRUD 기능을 잃지 않고 표 기반으로 재배치한다.
- 모바일은 열을 숨기지 않고 가로 스크롤과 고정 첫 열을 사용한다.
- 기존 화면의 `발생` 문구는 버튼·레이블·도움말·오류 메시지에서 모두 `주가 변동`으로 교체한다.
- 배정 편집에서 `뉴스 공개` 초를 직접 입력하고 장중 사건은 `주가 변동` 초도 직접 입력한다.
- 마감 사건의 `주가 변동` 칸은 숫자 입력 대신 읽기 전용 `거래 마감`으로 표시한다.
- 뉴스 공개와 주가 변동의 순서가 잘못되면 저장 전 인라인 오류를 표시하고 서버에서도 동일하게 거부한다.

### 7.2 정보 관리 표

| 열 | 내용 |
| --- | --- |
| 제목 | 단서 제목 |
| 연동 사건 | 사건명 또는 연관없음 |
| 공개 월 | 구매 가능 시작 월 |
| 가격 | 원 단위 |
| 상태 | 판매/중단/사건 종료 |
| 작업 | 정보 수정·판매 중단 |

- 기존 생성·수정·비활성화 버튼과 확인창은 유지한다.
- 표 행 전체 클릭으로 편집하지 않고 명시적 버튼만 작업을 실행한다.

### 7.3 종목 조회 표

| 열 | 내용 |
| --- | --- |
| 코드·기업명 | A~G, 이름 |
| 시작가 | 게임 시작 가격 |
| 현재가 | 현재 가격 |
| 변동 | 시작가 대비 변동률 |
| 상태 | 활성/비활성 |
| 작업 | 수정·비활성화·조회 |

- 기업 설명은 정해진 폭에서 줄바꿈하고 긴 내용은 펼쳐보기로 확인한다.
- 기존 생성·수정·비활성화 규칙을 유지한다.

### 7.4 월별 거래 통합 표

기존 월 선택 버튼과 갱신·주문 관련 동작은 유지하되 모든 월의 거래를 한 화면에서 확인할 수 있는 표를 기본으로 제공한다.

| 열 | 내용 |
| --- | --- |
| 월 | 거래가 체결된 월 |
| 시각 | 체결 시각 |
| 종목 | 코드·기업명 |
| 구분 | 매수/매도 |
| 수량 | 체결 주식 수 |
| 단가 | 체결 가격 |
| 총액 | 수량×단가 |
| 월 누계 | 해당 월 매수·매도 요약 |

- 월 경계 행 또는 그룹 헤더로 월별 구간을 분명히 나눈다.
- 데스크톱 한 화면에서는 표 전체를 보고, 모바일은 가로 스크롤을 사용한다.
- 빈 월도 `거래 없음`으로 구분해 1~12월 흐름을 놓치지 않게 한다.

## 10. 자동 테스트 계획

### Backend

- nullable 사건 연동 생성·수정·삭제
- 존재하지 않는 사건 연결 거부
- 기존 사전 예고값의 뉴스 공개 절대 시각 migration
- 뉴스 공개 전 비노출, 공개 후 사전 기사만 노출, 주가 변동 후 결과·가격 적용
- 장중·마감 사건의 뉴스 공개/주가 변동 순서와 거래시간 경계 검증
- 서버 재시작과 중복 타이머에서 뉴스 공개·주가 변동 각각 한 번 처리
- 적용 전 실제 단서 노출, 적용 후 공개 상점 제외
- 가짜 정보(`event_id=NULL`) 노출 유지
- 사건 적용과 구매가 동시에 진행될 때 한 번만 성공하고 잘못된 현금 차감 방지
- 구매 스냅샷이 사건 종료 후에도 보관함에 유지
- 관리자 사건·단서·종목 조회 계약 회귀 테스트

### Frontend

- 탭 진입만으로 주문창이 열리지 않음
- `주문하기`와 포트폴리오 액션으로만 워크스페이스 열림
- 주문창을 닫으면 포트폴리오 창도 닫힘
- 자산 바가 모든 게임 경로에 한 번만 표시됨
- 타이머가 인라인으로 렌더링되지 않고 기본 플로팅 상태임
- 보관함 3열과 `정보 읽기` 전 상세 본문 비노출
- 과거 사건 단서 제거와 구매 보관함 유지
- 업데이트 텍스트 버튼이 남지 않고 SVG 버튼에 접근 가능한 이름 존재
- 관리자 3개 표의 기존 작업 버튼 유지
- 사건 표에서 `뉴스 공개`와 `주가 변동`을 서로 다른 값으로 편집
- `발생` 사용자 문구가 사건 관리 화면에 남지 않음
- 전체 월 거래표의 그룹·합계·빈 월 표시
- 효과음 이벤트 중복 재생 방지와 음소거 저장
