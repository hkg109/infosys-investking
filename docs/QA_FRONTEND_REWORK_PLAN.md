# Frontend QA 후속 개선 계획

## 목적

기능 QA 1~11단계가 끝난 뒤 화면의 정보 구조와 사용성을 개선한다. 이번 작업의 기준은
다음 세 가지다.

1. 관리자·게임 화면을 네비게이션 중심의 여러 화면으로 나누어 긴 단일 페이지를 없앤다.
2. 수정·상세·주문 같은 주요 액션은 공통 커스텀 오버레이에서 바로 처리한다.
3. Hallmark를 디자인 검수 게이트로 사용해 화면별 시각 품질과 반응형 상태를 승인한다.

Hallmark의 사내 프로젝트·업로드 형식은 별도 합의가 필요하므로, 이 문서는 Hallmark를
디자인 리뷰 채널/도구로 사용한다는 전제에서 작성했다. 연동 API나 계정 권한을 코드에
추가하지 않으며, 리뷰 링크·스크린샷·승인자를 PR에 기록한다.

나누어 호출하되, 응답 계약을 깨지 않고 Frontend에서 조합한다.

## 12단계 — 네비게이션과 화면 분리

### 화면 구조

기존 `/admin`, `/game` 주소는 호환용으로 유지하고 각각 기본 하위 화면으로 redirect한다.
하위 화면은 React Router의 nested route로 구현해 직접 URL 접근과 브라우저 뒤로가기를 지원한다.

| 영역 | URL | 화면 책임 |
|---|---|---|
| 관리자 | `/admin/overview` | 게임 상태, 시작·일시정지·종료·초기화 |
| 관리자 | `/admin/participants` | 참가자 이름, 접속 상태, 현금·보유 주식 |
| 관리자 | `/admin/companies` | 종목 생성·수정·비활성화 |
| 관리자 | `/admin/events` | 사건 원본, 월별 수동·랜덤 배정 |
| 관리자 | `/admin/missions` | 비밀 미션 생성·배정·진행 |
| 관리자 | `/admin/intelligence` | 추가 시장정보·포인트 관리 |
| 관리자 | `/admin/results` | 월별 결과, 최종 순위, 초기화 전 확인 |
| 참가자 | `/game/market` | 종목·현재가·뉴스·시장 상태 |
| 참가자 | `/game/orders` | 매수·매도·주문 결과·보유 현황 |
| 참가자 | `/game/history` | 월별 거래와 주가 차트 |
| 참가자 | `/game/ranking` | 익명 순위와 내 순위 |
| 참가자 | `/game/missions` | 개인 미션·포인트·추가 정보 |
| 참가자 | `/game/profile` | 닉네임·로그아웃·PIN 복구 안내 |

### 구현 규칙

- `PageShell`이 상단 네비게이션, 현재 메뉴, 페이지 제목, 연결 상태를 공통으로 렌더링한다.
- 한 화면에는 핵심 작업 하나만 배치하고 목록·편집·상세를 세로로 무한히 쌓지 않는다.
- 모바일에서는 상단 메뉴를 가로 스크롤 가능한 탭 또는 접이식 메뉴로 바꾼다.
- 현재 메뉴는 URL과 `aria-current="page"`로 표시한다.
- 기존 링크와 QR 주소가 깨지지 않도록 `/admin`은 `/admin/overview`, `/game`은
  `/game/market`으로 replace redirect한다.
- 메뉴 이동 중 작성 중인 주문이나 편집 내용이 있으면 저장·취소를 먼저 선택하게 한다.

### 검증

- 모든 하위 URL을 새로고침해도 올바른 화면이 열린다.
- 관리자와 참가자 권한이 다른 URL로 이동할 수 없다.
- 320·390·768·1280px에서 메뉴가 콘텐츠를 가리지 않는다.
- 브라우저 뒤로가기·앞으로가기가 메뉴 상태와 일치한다.
- 페이지 전환 뒤 Socket·폴링 구독이 중복되지 않는다.

## 13단계 — 커스텀 액션 오버레이

여기서 말하는 커스텀 탭은 새 브라우저 탭이 아니라 현재 화면 위에 여는 앱 내부 Modal/Drawer다.
목록의 수정·상세 버튼에서 즉시 열리며 배경 목록과 선택한 대상을 유지한다.

### 공통 컴포넌트

`ActionDialog`를 하나의 진입점으로 만들고 `mode`에 따라 데스크톱에서는 우측 Drawer,
작은 화면에서는 하단 Sheet 또는 전체 화면 편집 화면으로 전환한다.

- 열릴 때 첫 입력 요소에 포커스 이동
- 닫힐 때 열기 버튼으로 포커스 복귀
- ESC·닫기 버튼·배경 클릭 정책 통일
- 저장 중 중복 제출 방지와 로딩 상태 표시
- 오류는 입력 옆과 오버레이 상단에 표시하고 입력값을 보존
- 미저장 변경이 있으면 닫기 전 저장·폐기·계속 편집 선택
- `body` 스크롤 잠금과 `aria-modal`, `aria-labelledby` 제공
- 편집 대상은 `?edit=<id>` 또는 `?detail=<id>`로 복구 가능하게 설계

### 적용 대상

| 화면 | 액션 | 오버레이 내용 |
|---|---|---|
| 종목 | 수정·추가 | 코드, 이름, 설명, 초기 가격, 활성 상태 |
| 사건 | 수정·추가 | 뉴스, 결과, 영향 종목·변동률 |
| 배정 | 상세·수정 | 월, 발생 구간, 예고 시각, 충돌 결과 |
| 미션·정보 | 수정·추가 | 조건, 보상, 공개 월, 구매 정보 |
| 주문 | 매수·매도 | 종목 상세, 수량, 예상 금액, 최종 확인 |
| 거래·차트 | 상세 | 체결 시각, 가격, 수량, 사건 영향 |
| 참가자 | 상세 | 현금·보유 주식·온라인 상태, 개인정보 경고 |

### 검증

- 수정 버튼을 눌렀을 때 대상 행을 잃지 않고 즉시 오버레이가 열린다.
- 저장 성공 시 오버레이가 닫히고 목록 한 건만 최신 데이터로 갱신된다.
- 저장 실패·네트워크 단절·중복 클릭 시 입력값과 오류가 유지된다.
- ESC·취소·바깥 클릭의 동작이 화면마다 다르지 않다.
- 키보드 탭이 오버레이 밖으로 빠져나가지 않고, 닫은 뒤 원래 버튼으로 돌아온다.
- 참가자 개인정보는 관리자 오버레이 밖이나 중계 화면에 노출되지 않는다.

## 14단계 — 디자인 시스템과 Hallmark 검수

### 먼저 고정할 디자인 자산

- 색상·간격·모서리·그림자·타이포그래피 토큰
- `PageShell`, `NavigationBar`, `ActionDialog`, `Toast`, `StatusBadge`, `EmptyState`
- 로딩·오류·빈 상태·저장 중·저장 성공·권한 없음 상태
- 데스크톱 1920×1080, 노트북 1280×800, 모바일 폭 390px 기준 화면 캡처

### Hallmark 리뷰 패키지

각 화면 PR에 다음을 함께 올린다.

1. 변경 전·후 캡처 또는 디자인 링크
2. 관리자/게임/중계의 대표 화면과 액션 오버레이 상태
3. 1920·1280·768·390px별 캡처
4. 호버·포커스·비활성·오류·빈 상태 캡처
5. Hallmark 리뷰 링크, 리뷰어, 승인일, 남은 이슈

### Hallmark 체크리스트

| 항목 | 확인 내용 |
|---|---|
| 정보 구조 | 메뉴 이름과 순서가 사용자의 작업 순서와 일치하는가 |
| 일관성 | 버튼·오버레이·상태 배지·오류 문구가 화면마다 같은가 |
| 가독성 | 타이머·주가·순위·오류가 큰 화면과 모바일에서 읽히는가 |
| 상호작용 | 호버뿐 아니라 키보드 포커스와 터치에서도 같은 기능이 가능한가 |
| 안전성 | 저장·삭제·초기화에 대상, 영향, 취소 방법이 분명한가 |
| 개인정보 | 공개 중계와 참가자 화면에 관리자 정보가 섞이지 않는가 |
| 접근성 | 색상만으로 상태를 구분하지 않고 레이블·포커스가 있는가 |

Hallmark에서 `수정 필요`가 나오면 기능 PR을 바로 완료 처리하지 않는다. 수정 후 같은
화면을 재검토하고, 승인되지 않은 화면은 행사 기능 플래그에서 제외한다.

## 22단계 — 통합 회귀와 행사 인계 (15단계에서 이관)

기존 F-24 시나리오에 네비게이션·오버레이·디자인 검수를 포함한다.

1. 관리자 창, 참가자 A/B 창, `/broadcast` 창을 각각 별도 세션으로 연다.
2. 메뉴 이동 중 관리자 시작, 참가자 주문, 중계 타이머가 끊기지 않는지 확인한다.
3. 종목·사건·미션을 오버레이에서 저장하고 다른 화면에 최신 결과가 반영되는지 확인한다.
4. 장중 사건 예고·정지·결과·재개, 일시정지·재접속·종료·초기화를 반복한다.
5. 320/390/768px에서 가로 넘침과 오버레이 잘림을 확인한다.
6. 브라우저 Console error, React key 경고, 중복 Socket 구독을 확인한다.
7. Hallmark 승인 캡처와 자동 테스트 결과를 PR에 첨부한다.

### 완료 판정

- `npm --prefix client test` 통과
- `npm --prefix client run build` 통과
- F-24 실제 브라우저 시나리오 통과
- Hallmark 검수 승인 또는 예외 승인 기록
- 미해결 P0/P1 UI 버그 없음
- 행사 전 기능 플래그·롤백 방법·운영자 메뉴 안내 완료
