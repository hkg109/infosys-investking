# QA 26~28단계 협업 개발 계획

## 1. 문서 목적

이 문서는 행사 전 최종 QA에서 확인된 정보상점, 장중 사건 알림, 기업 설명, 하단 문구 및 최종 순위 실명 공개 작업을 지석(Backend)과 재헌(Frontend)이 나누어 개발하기 위한 인계 문서다.

작업은 기능 의존성을 기준으로 **3단계, PR 3개**로 압축한다. 같은 단계의 Backend와 Frontend 수정은 하나의 브랜치에서 함께 검증하며, 담당자가 서로 다른 경우 Backend 계약을 먼저 확정한 뒤 Frontend를 연결한다.

## 2. QA 요구사항

1. 정보상점에서 실제 현금으로 정보를 구매할 수 있어야 한다.
2. 구매 가능한 정보 카드의 버튼 문구를 정보 제목이 포함된 문구 대신 `정보 구매`로 통일한다.
3. 장중 사건 발생 시 화면 오른쪽 아래에 제목만 표시하는 커스텀 알림을 띄운다.
4. 장중 사건 알림을 누르면 뉴스 탭으로 이동해 해당 기사를 바로 열어야 한다.
5. 시장의 기업 이름을 누르면 이름 옆에 작은 사각형 기업 설명 카드를 띄운다.
6. 기업 설명 카드는 커스텀 디자인을 사용하고 `×` 버튼과 `Esc` 키로 닫을 수 있어야 한다.
7. 공통 하단 문구를 `한양대학교 정보시스템학과 16대 학생회 휘연 주최`로 변경한다.
8. 게임 진행 중에는 참가자 이름을 익명으로 유지하고, 투자왕이 결정된 뒤에는 실제 이름을 표시한다.

## 4. 26단계 — 정보상점 구매 복구

### 4.1 Backend 작업

- `GET /api/intelligence/me`가 현재 사용자의 현금, 판매 중인 정보 및 구매 내역을 정상 반환하는지 확인한다.
- 구매 API가 참가 세션을 올바르게 인식하는지 확인한다.
- 게임 상태가 `RUNNING`일 때만 구매를 허용한다.
- `availableRound`가 현재 월 이하인 정보만 구매할 수 있게 한다.
- 서버가 요청에 포함된 가격을 신뢰하지 않고 DB의 최신 가격으로 검증한다.
- 다음 처리를 하나의 DB Transaction으로 묶는다.
  1. 사용자와 정보 행 잠금
  2. 게임 상태·공개 월·가격·잔액 재검증
  3. 현금 차감
  4. 구매 기록 저장
- 같은 사용자가 같은 정보를 다시 구매하지 못하게 한다.
- 실패 시 현금만 차감되거나 구매 기록만 생성되는 부분 성공이 없어야 한다.
- 구매 성공 응답은 변경된 현금과 최신 구매 내역을 Frontend가 즉시 갱신할 수 있는 형태여야 한다.

### 4.2 Frontend 작업

- 상점 진입 시 최신 정보와 현금을 불러온다.
- 구매 완료 후 상점과 보관함을 다시 조회하거나 성공 응답으로 동시에 갱신한다.
- 구매 성공 전에 카드가 보관함에 표시되지 않도록 한다.
- 네트워크 오류가 발생해도 구매 요청을 자동 재전송하지 않는다.
- 실패 메시지는 현금 부족, 공개 전, 게임 종료, 인증 만료 및 가격 변경을 구분한다.
- 구매 가능한 카드의 버튼 문구는 제목과 관계없이 `정보 구매`로 표시한다.

| 카드 상태 | 버튼 문구 |
|---|---|
| 구매 가능 | `정보 구매` |
| 구매 완료 | `보관함에 있음` |
| 공개 전 | `아직 구매할 수 없음` |
| 현금 부족 | `현금이 부족함` |
| 처리 중 | `구매 처리 중…` |

### 4.3 자동·수동 테스트

- 현금이 충분한 사용자의 최초 구매 성공
- 구매 금액과 실제 현금 차감액 일치
- 구매 직후 보관함에서 정보 본문 확인
- 새로고침 및 재접속 후 구매 내역 유지
- 같은 정보의 중복 구매 차단
- 두 기기에서 동시에 같은 정보를 구매할 때 한 요청만 성공
- 현금 부족, 공개 전, `WAITING`, `PAUSED`, `FINISHED` 상태에서 구매 차단
- 인증되지 않은 사용자가 비공개 정보 본문을 조회하지 못함

## 5. 27단계 — 장중 사건 알림·기업 설명 UI

### 5.1 장중 사건 Socket 계약

장중 사건 알림은 기존 `market:event:warning`과 `market:event:breaking` 흐름을 사용한다. 실제 payload에는 최소한 다음 값이 있어야 한다.

```json
{
  "gameEventId": "uuid",
  "title": "[속보] 사건 제목",
  "triggerPhase": "INTRADAY"
}
```

- 참가자에게 허용된 사건 제목과 식별자만 전송한다.
- 알림 단계에서 미공개 기사 본문이나 주가 변동 결과를 노출하지 않는다.
- 같은 `gameEventId`를 중복 수신해도 알림을 한 번만 생성한다.
- 재접속 시 이미 공개된 뉴스는 뉴스 목록으로 복구하되 오래된 알림을 새 알림처럼 반복 표시하지 않는다.

### 5.2 장중 사건 알림 UI

- 화면 오른쪽 아래에 브라우저 기본 알림이 아닌 커스텀 알림을 표시한다.
- 알림에는 **사건 제목만** 표시한다.
- 알림 전체를 버튼처럼 클릭할 수 있게 한다.
- 클릭하면 게임 화면의 뉴스 탭으로 전환하고 `gameEventId`가 같은 기사를 펼친 뒤 제목으로 초점을 이동한다.
- 여러 사건을 연속 수신하면 순서가 보존되도록 대기열 또는 스택으로 처리한다.
- 모바일에서는 하단 네비게이션과 겹치지 않게 안전 여백을 적용한다.
- 키보드 `Enter`와 `Space`로 열 수 있게 하고 알림 목적을 스크린리더에 전달한다.
- 알림이 사라져도 공개된 뉴스는 뉴스 탭에 계속 남아야 한다.

### 5.3 기업 설명 카드 UI

시장 종목 목록의 기업 이름을 일반 텍스트가 아닌 접근 가능한 버튼으로 변경한다. 버튼을 누르면 해당 이름 옆에 작은 사각형 설명 카드를 표시한다.

카드 표시 정보:

- 기업 이름
- 업종
- 기업 설명
- 현재 주가
- 현재 월 등락률

동작 규칙:

1. 기업 이름을 누르면 해당 기업 옆에 설명 카드를 연다.
2. 다른 기업 이름을 누르면 기존 카드를 닫고 선택한 기업 카드를 연다.
3. 카드 오른쪽 위의 `×` 버튼으로 닫는다.
4. `Esc` 키로 닫고 초점을 원래 기업 이름으로 돌려보낸다.
5. 카드 안을 눌러도 주문 선택이나 매수·매도 동작이 실행되지 않게 이벤트를 분리한다.
6. 화면 가장자리에서는 카드 위치를 자동 조정한다.
7. 모바일에서는 이름 옆 공간이 부족하면 해당 종목 행 아래에 표시한다.
8. 브라우저 기본 팝오버가 아닌 프로젝트 디자인 토큰을 사용하는 커스텀 배경, 테두리, 그림자 및 닫기 버튼을 적용한다.

예상 형태:

```text
한양양조  ┌────────────────────────×┐
           │ 주류                    │
           │ 과일 막걸리를 생산하고  │
           │ 대학가 술집에 공급합니다.│
           │ 11,800원 · 이번 달 +13% │
           └─────────────────────────┘
```

기업 목록 API에 업종 또는 설명이 이미 포함되어 있다면 Backend 계약을 변경하지 않는다. 필드가 없다면 지석이 기존 공개 기업 응답에 `industry`, `description`을 추가하고 문서와 테스트를 함께 수정한다.

### 5.4 공통 하단 문구

모든 참가자·관리자 공개 화면에서 기존 문구를 다음 문구로 교체한다.

```text
한양대학교 정보시스템학과 16대 학생회 휘연 주최
```

공통 레이아웃에서 한 번만 변경하고 화면별로 같은 문구를 중복 구현하지 않는다.

### 5.5 자동·수동 테스트

- 장중 사건 수신 시 제목만 표시
- 알림 클릭 시 뉴스 탭과 정확한 기사 열림
- 동일 사건 중복 알림 방지
- PC·모바일에서 알림이 타이머와 네비게이션을 가리지 않음
- 모든 기업의 설명 카드 열기 및 `×`·`Esc` 닫기
- 다른 기업 선택 시 카드 내용과 위치 갱신
- 카드 조작이 주문 입력에 영향을 주지 않음
- 키보드만으로 기업 카드와 사건 알림 사용 가능
- 공통 하단 문구가 참가자·관리자·중계 화면에서 일관되게 표시

## 6. 28단계 — 최종 투자왕 실명 공개

### 6.1 개인정보 공개 규칙

| 게임 상태 | 다른 참가자 이름 | 본인 표시 | 최종 TOP 3 |
|---|---|---|---|
| `WAITING` | 비공개 | 본인만 식별 가능 | 비공개 |
| `RUNNING` | 비공개 | 본인만 식별 가능 | 익명 자산 순위 |
| `PAUSED` | 비공개 | 본인만 식별 가능 | 익명 자산 순위 |
| `FINISHED` | 공개 | 실제 이름 | 실제 이름 공개 |

- 실명 공개 판단은 클라이언트가 아닌 서버의 게임 상태를 기준으로 한다.
- 진행 중 순위 Socket, REST 응답 및 중계 Feed에 다른 참가자의 이름이 포함되지 않아야 한다.
- 게임 종료가 확정된 뒤의 최종 순위 응답에만 실제 이름을 포함한다.
- 공동 순위에서도 모든 대상자의 실제 이름과 순위를 표시한다.
- 게임 초기화 후에는 다시 익명 정책으로 돌아간다.

### 6.2 Frontend 표시

- 참가자 게임 화면의 최종 결과에 TOP 3 실제 이름을 표시한다.
- `내 순위`에는 본인의 실제 이름과 최종 자산을 표시한다.
- 대형 중계 화면의 `투자왕이 결정되었습니다` 장면에도 실제 이름을 표시한다.
- 게임 종료 전 렌더링된 익명 순위가 종료 후 실명 순위로 즉시 교체되어야 한다.
- 종료 후 새로고침하거나 재접속해도 동일한 최종 결과를 복구한다.

### 6.3 자동·수동 테스트

- `WAITING`, `RUNNING`, `PAUSED` 응답에 타인 실명 없음
- `FINISHED` 이후 최종 순위에 실제 이름 포함
- 참가자 화면과 중계 화면의 TOP 3 결과 일치
- 동점자 실명과 공동 순위 정상 표시
- 종료 후 재접속 시 실명 최종 결과 복구
- 게임 초기화 후 진행 순위가 다시 익명으로 표시
