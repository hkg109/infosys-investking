# 19단계 — 사건 수동 배정 전용화

기준 main: `0a4cbf9` (18단계 PR #45 병합). 브랜치: `codex/manual-event-scheduling`.

## 변경

- 관리자 화면에서 무작위 개수/예고 설정과 랜덤 배정 버튼을 제거했다.
- 모든 배정 저장은 `PUT /api/events/admin/schedule`로 보낸다.
- 게임 시작과 서버 복구 시 랜덤 배정을 만들던 경로를 제거했다.
- 배정 미설정/빈 배정은 사건 없이 진행한다. 저장된 배정의 월·순서·발생 시각은 보존한다.
- 과거 RANDOM 배정과 관련 DB 값은 보존한다. 새 배정 저장은 MANUAL만 사용한다.
- 기존 랜덤 API는 관리자 인증 후 410 `MANUAL_SCHEDULE_ONLY`를 반환하며 DB를 변경하지 않는다.
- 사건/종목 안내와 API·인계 문서의 현재 동작을 수정했다.

## 검증

- Client 테스트 73개 통과, 배포 빌드 성공. 제거한 랜덤 입력 전용 테스트는 함께 제거했다.
- Server 실제 임시 PostgreSQL 통합 테스트 55개 통과, 실패/건너뜀 없음.
- 미설정 게임 시작 준비·종료 상태 복구 시 배정 생성 없음, 빈 수동 배정 유지 확인.
- 저장된 배정(과거 RANDOM 모드 포함)을 시작/일시정지 복구가 변경하지 않음 확인.
- 폐기된 API의 410과 기존 배정 보존, 관리자 인증·Origin 제한 확인.
- 기존 장중 예고/거래정지/가격 변경/한 번만 반영하는 동작 검증 유지.
- 격리된 실제 브라우저: 수동 시각 120→60초 저장, 전체 배정 제거·빈 배정 저장,
  게임 시작 성공 후 빈 배정 유지, 무작위 컨트롤 없음 확인. 콘솔 warning/error 없음.

## 배포와 QA 범위

DB 구조 변경 및 추가 마이그레이션 없음. 서버와 Client를 함께 배포한다.
기존 배정은 자동으로 지우지 않으므로 운영자는 시작 전에 저장된 배정표를 확인한다.
이 PR은 배포 서버에 직접 적용하지 않는다. 전체 회귀 QA는 22단계, 실물 스마트폰 검증은 제외한다.
