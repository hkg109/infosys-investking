# QA 10단계 Frontend — 대형 스크린 중계 (F-22~23)

## 구현

- 로그인 없이 접근하는 `/broadcast` 16:9 중계 화면을 추가했다. 메인 화면에서 링크로 열 수 있으며 전체 화면 버튼을 제공한다.
- 공개 `GET /api/broadcast`만 조회한다. 요청에 쿠키를 보내지 않고 응답 캐시를 사용하지 않는다.
- 대기, 거래, 사건 예고, 장중 속보, 월 결과, 일시정지, 최종 집계, 확정 순위 장면을 서버 상태에 따라 전환한다.
- 시장 종목·현재가·월 시가 대비 변동률, 익명 TOP 3(공동 3위 포함), 공개 뉴스를 보여준다. 닉네임·사용자 ID·현금·보유 주식·미션·구매 정보는 표시하지 않는다.
- 장중 예고는 예정 시각만 보이고 사건 제목·결과는 노출하지 않는다. 사건 적용 뒤 결과와 영향 종목을 속보로 표시한다.
- 첫 접속에서는 기존 사건 결과를 속보로 재연출하지 않는다. 이후 새 `gameEventId`만 속보로 연출하며, 게임 초기화 시 기록을 비운다.
- 서버가 제안한 `pollAfterMs` 간격으로 순차 조회한다. 오류 발생 시 2→4→8초 재시도하고 마지막 화면 위에 연결 오류를 명시한다. 서버 시각으로 타이머를 보정한다.
- 애니메이션 감소 설정을 존중한다.

## 행사 전 브라우저 확인

- [ ] 실제 서버·PostgreSQL에 연결된 `/broadcast`를 프로젝터 1920×1080 화면에 표시하고 글자 크기·잘림을 확인한다.
- [ ] 관리자 시작 → 거래 → 일시정지·재개 → 장중 예고·사건 → 월 마감 → 종료 순서대로 장면과 타이머가 바뀌는지 확인한다.
- [ ] 참가자 여러 명의 익명 순위와 공동 3위가 나오며 이름·보유 자산 상세가 보이지 않는지 확인한다.
- [ ] 중계 화면을 새로고침하거나 네트워크를 잠시 끊었다가 연결해도 결과를 중복 속보로 재생하지 않는지 확인한다.
- [ ] 종료 직후 집계 중 화면이 표시되다가 확정 최종 순위로 전환되는지 확인한다.
- [ ] 초기화 후 이전 게임의 뉴스·결과·순위가 남지 않는지 확인한다.
