# QA 8단계 — 개인 비밀 미션 UI

## 범위

최신 main `458df2e`를 기준으로 F-18~19와 D-02를 구현했습니다. 기존 미션 Backend 계약을 사용하며 서버 코드는 변경하지 않았습니다.

- 관리자: 미션 조회·생성·수정·비활성화·재활성화, 유형별 목표 검증, 참가자별 배정·진행·완료 조회.
- 사용자: 본인 미션, 조건과 판정 시점, 진행도, 완료 상태, 보상 및 정보 포인트.
- 대기 상태에서만 관리자 변경 허용. 요청 중 중복 동작 차단, 실패한 변경 자동 재전송 금지, 재조회 후 변경 재개.
- 사용자 변경·세션 만료 시 비공개 캐시 제거. Socket 및 게임 상태 갱신을 통한 서버 재조회.

- Production build: `npm --prefix client run build` — 성공.

- 미션 입력 범위, 응답 검증, 서버 완료 상태, 세션 변경, 관리 가능 상태, 쿠키 인증, 자동 재시도 금지를 검증했습니다.

## 실제 브라우저 검증

2026-09-18, 로컬 API 3003 / Vite 5176 / 격리 PostgreSQL 55432에서 수행했습니다. 실제 운영 DB는 사용하지 않았습니다.

- 관리자 로그인 → 미션 생성 → 보상 수정(40P) → 비활성화 → 재활성화.
- 참가자 등록 → 대기 중 미배정 표시 → 관리자 시작 → 비밀 미션 배정.
- 매수 1회 후 진행도 1/2, 매도 1회 후 2/2와 완료·40P 지급 표시.
- 새로고침 후 완료 상태와 40P 유지, 관리자 조회에서도 해당 참가자의 완료·보상 확인.
- 게임 시작 후 관리자 미션 수정 버튼 비활성화 확인.
- 관리자·사용자 브라우저 콘솔 오류/경고 없음.
- 사용자 뷰포트 320/360/390/412/430/768px, 관리자 320/390/412/768px에서 문서 가로 넘침 없음. 390px 사용자 화면 시각 확인.

실물 iPhone·삼성 기기 테스트는 합의된 범위에서 제외했습니다. 브라우저 폭 검증은 각 모바일 OS의 실물 실행을 의미하지 않습니다. 정보 포인트 구매 기능은 다음 단계이며 이번 변경에 포함되지 않습니다.
