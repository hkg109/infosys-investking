# 18단계 검증 — 관리자 참가자 자산 수정

기준: 2026-09-25, main `b5c0111` (#44 현금 정보상점 UI 병합 후).
브랜치: `codex/admin-asset-adjustments`.

## 구현

- 관리자 참가자 상세창에서 변경 후 현금과 선택 종목 보유 수량을 지정한다.
- 사유 입력 → 변경 전후 확인 → 수정 확정, 최근 50건 기록 조회.
- 대기/일시정지 제한, 관리자 인증, Origin 제한, 동시 수정 충돌 검출.
- 현금·주식·감사 기록을 단일 트랜잭션으로 저장한다.
- 응답 유실 후 같은 요청 번호로 결과 확인, 탭 새로고침 후 요청 복구.
- 변경 후 순위 이벤트 및 기존 자산 조회를 통해 참가자 화면을 갱신한다.
- 상세 API 및 운영 제약: [ADMIN_ASSET_API.md](ADMIN_ASSET_API.md).

## 자동 검증 결과

- Client `npm test`: 74개 통과.
- Client `npm run build`: 통과. 최신 main의 폰트 의존성을 `npm ci`로 설치 후 확인.
- Server `npm run test:integration`: 실제 임시 PostgreSQL 17 DB, 55개 통과, 건너뜀 없음.
- 신규 서버 검증 9개(상위 테스트 포함): 입력 검증, 원자적 저장, 동일 요청 동시 재시도,
  오래된 값 충돌, 서로 다른 수정 동시 실행, PAUSED, 비활성 종목/0주,
  총자산 초과 롤백, RUNNING/FINISHED 제한, 사용자 잠금 대기 중 재개,
  관리자 인증/Origin, 감사 기록, 커밋 후 갱신 실패와 재시도.
- 신규 Client 검증: 절대 금액·수량 및 변경 전 값, 입력 한계, 응답 유실/잘못된 응답,
  요청 UUID 유지, 충돌 오류, 중복 성공 응답.

## 실제 브라우저 검증

운영 DB와 분리된 로컬 테스트 세션에서 확인했다.

- 테스트 참가자 생성 후 현금 1,000,000 → 850,000원과 A 종목 0 → 7주를 함께 저장.
- 관리자 목록/상세/기록과 다른 참가자 창의 현금 850,000원·주식 70,000원·총자산
  920,000원 반영 확인.
- 두 번째 관리자 창이 오래된 850,000원을 편집하는 동안 첫 창에서 800,000원으로 수정.
  두 번째 창의 700,000원 요청은 충돌 메시지와 함께 차단되어 덮어쓰지 않음.
- ESC에서 미저장 경고, 폐기 후 상세 보기 버튼으로 포커스 복귀 확인.
- 데스크톱 1280px와 390px 편집창 확인. 390px에서 문서/편집창 폭 390px, 가로 넘침 없음.
- 관리자 창 콘솔 warning/error 없음(정상 수정 경로).

## QA 범위

이 PR은 18단계 관련 검증과 기존 자동 테스트를 실행한다. **전체 운영 흐름 회귀 QA는
15단계에서 22단계로 이관**한다. 실제 아이폰·삼성폰 테스트는 사용자 결정으로 제외한다.
브라우저 좁은 화면 검증은 실물 기기 검증으로 간주하지 않는다.
